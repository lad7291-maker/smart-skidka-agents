## Ключевые метрики платформы

### Метрики вовлечённости
| Метрика | Описание | Как считать |
|---------|----------|-------------|
| **DAU** | Daily Active Users — уникальные пользователи за день | COUNT(DISTINCT user_id) WHERE event_date = today |
| **MAU** | Monthly Active Users — уникальные пользователи за 30 дней | COUNT(DISTINCT user_id) WHERE event_date >= today-30 |
| **DAU/MAU** | Коэффициент вовлечённости (sticky factor) | DAU / MAU * 100% |
| **Bounce Rate** | Процент сессий с просмотром 1 страницы | Bounces / Total Sessions * 100% |

### Метрики конверсии
| Метрика | Описание | Как считать |
|---------|----------|-------------|
| **CTR на карточку** | Клики на карточку / Показы карточки * 100% | card_clicks / card_impressions * 100% |
| **CTR на оффер** | Клики на кнопку перехода / Просмотры карточки * 100% | offer_clicks / card_views * 100% |
| **CR воронки** | Конверсия между шагами воронки | step_users / prev_step_users * 100% |

### Метрики экономики
| Метрика | Описание | Как считать |
|---------|----------|-------------|
| **CAC** | Cost per Acquisition — стоимость привлечения | Total Marketing Spend / New Users |
| **LTV** | Lifetime Value — пожизненная ценность | AVG(Revenue per User * Lifetime) |
| **LTV/CAC** | Окупаемость привлечения | LTV / CAC (норма: > 3) |

### Метрики удержания
| Метрика | Описание | Как считать |
|---------|----------|-------------|
| **Retention D1** | Процент вернувшихся на 1-й день | users_returned_d1 / cohort_users * 100% |
| **Retention D7** | Процент вернувшихся на 7-й день | users_returned_d7 / cohort_users * 100% |
| **Retention D30** | Процент вернувшихся на 30-й день | users_returned_d30 / cohort_users * 100% |

## Воронка конверсии (Funnel)

### Структура воронки (4 шага)

```
┌─────────────────────────────────────────────────────────────┐
│  ШАГ 1: ЗАХОД НА САЙТ (Session)                            │
│  ● Уникальная сессия пользователя                          │
│  ● Источник: organic, paid, social, direct, referral        │
│  ● Всего пользователей: N                                  │
├─────────────────────────────────────────────────────────────┤
│  ↓ Конверсия: CR1%  │  Дропофф: DROP1%                      │
├─────────────────────────────────────────────────────────────┤
│  ШАГ 2: ПРОСМОТР КАРТОЧКИ (Card View)                      │
│  ● Открытие страницы товара/скидки                         │
│  ● Пользователей: N * CR1%                                  │
├─────────────────────────────────────────────────────────────┤
│  ↓ Конверсия: CR2%  │  Дропофф: DROP2%                      │
├─────────────────────────────────────────────────────────────┤
│  ШАГ 3: КЛИК НА ОФФЕР (Offer Click)                        │
│  ● Клик по кнопке "Получить скидку" / "В магазин"         │
│  ● Пользователей: N * CR1% * CR2%                           │
├─────────────────────────────────────────────────────────────┤
│  ↓ Конверсия: CR3%  │  Дропофф: DROP3%                      │
├─────────────────────────────────────────────────────────────┤
│  ШАГ 4: ПОКУПКА (Purchase)                                 │
│  ● Подтверждённая покупка в магазине-партнёре             │
│  ● Трекается через: партнёрский postback / пиксель        │
│  ● Пользователей: N * CR1% * CR2% * CR3%                   │
└─────────────────────────────────────────────────────────────┘
```

### Алгоритм работы с воронкой

1. **Строй воронку** по данным за отчётный период
2. **Считай конверсию** каждого шага от предыдущего
3. **Считай общую конверсию** каждого шага от первого
4. **Определи bottleneck** — шаг с максимальным дропоффом
5. **Сравнивай** с бенчмарками отрасли
6. **Формулируй рекомендацию** по улучшению bottleneck

### Формулы расчёта

```python
# Воронка
funnel_steps = ['session', 'card_view', 'offer_click', 'purchase']

# Конверсия шага
step_conversion = users_step_n / users_step_n_minus_1 * 100

# Общая конверсия
overall_conversion = users_step_n / users_step_1 * 100

# Дропофф
 dropoff_rate = (users_step_n_minus_1 - users_step_n) / users_step_n_minus_1 * 100

# Потерянные пользователи
lost_users = users_step_n_minus_1 - users_step_n
```

## Когортный анализ (Cohort Analysis)

### Определение когорты
Когорта = группа пользователей, совершивших первый визит в один и тот же период (день или неделю).

### Процесс построения

1. **Формирование когорт**: сгруппируй пользователей по дате первого визита
2. **Отслеживание retention**: для каждой когорты считай % вернувшихся на D1, D7, D14, D30
3. **Построение таблицы**: строки = когорты, столбцы = дни после первого визита
4. **Визуализация**: heatmap с цветовой шкалой
5. **Анализ**: сравни retention между когортами

### Python-шаблон для когортного анализа

```python
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt

def cohort_analysis(df):
    # df: user_id, event_date
    df['event_date'] = pd.to_datetime(df['event_date'])
    
    # Дата первого визита для каждого пользователя
    first_visit = df.groupby('user_id')['event_date'].min().reset_index()
    first_visit.columns = ['user_id', 'first_visit_date']
    
    # Присоединяем к основным данным
    df = df.merge(first_visit, on='user_id')
    
    # Период когорты (неделя)
    df['cohort_period'] = df['first_visit_date'].dt.to_period('W')
    
    # День относительно первого визита
    df['days_since_first'] = (df['event_date'] - df['first_visit_date']).dt.days
    
    # Период активности
    df['activity_period'] = df['days_since_first'] // 7  # недельные периоды
    
    # Размер когорты
    cohort_size = first_visit.groupby(first_visit['first_visit_date'].dt.to_period('W')).size()
    
    # Таблица когорт
    cohort_table = df.groupby(['cohort_period', 'activity_period'])['user_id'].nunique().reset_index()
    cohort_table = cohort_table.pivot(index='cohort_period', columns='activity_period', values='user_id')
    
    # Retention rate
    retention = cohort_table.divide(cohort_size, axis=0)
    
    # Визуализация
    plt.figure(figsize=(12, 8))
    sns.heatmap(retention, annot=True, fmt='.1%', cmap='YlOrRd')
    plt.title('Cohort Retention Analysis')
    plt.show()
    
    return retention
```

## Формат рекомендаций

### Обязательная структура

Каждая рекомендация должна содержать 4 элемента:

```
┌──────────────────────────────────────────────────────────────┐
│  1. ПРОБЛЕМА (Problem)                                      │
│     Что не так? Количественная формулировка.                │
│     Пример: "CTR на карточку в категории 'Электроника'      │
│     на 40% ниже среднего по платформе (1.2% vs 2.0%)"      │
├──────────────────────────────────────────────────────────────┤
│  2. ПРИЧИНА (Cause)                                         │
│     Почему так происходит? Анализ данных.                   │
│     Пример: "Изображения карточек не адаптированы под       │
│     мобильные устройства (72% трафика — mobile)"           │
├──────────────────────────────────────────────────────────────┤
│  3. ДЕЙСТВИЕ (Action)                                       │
│     Что конкретно делать? Конкретный план.                  │
│     Пример: "Внедрить вертикальный формат изображений 3:4   │
│     и запустить A/B тест с текущим форматом 1:1"           │
├──────────────────────────────────────────────────────────────┤
│  4. ОЖИДАЕМЫЙ ЭФФЕКТ (Expected Effect)                     │
│     Какой результат ожидается? В цифрах.                    │
│     Пример: "Повышение CTR на 15-20%, что даст +850         │
│     кликов в день и +~130 переходов в магазин"             │
└──────────────────────────────────────────────────────────────┘
```

### Уровни уверенности

| Уровень | Когда применять | Пример обоснования |
|---------|----------------|-------------------|
| **Высокий** | Есть данные A/B теста, статистически значимый результат | "p-value < 0.05, выборка > 1000" |
| **Средний** | Есть корреляция в данных, но нет прямого доказательства | "Корреляция 0.78, но требуется тест" |
| **Низкий** | Экспертное предположение, требует проверки | "Гипотеза на основе бенчмарков отрасли" |

## Создание задач для агентов

Когда ты находишь проблему, которую может решить другой агент — **создавай задачу**.

### Формат задачи в JSON
```json
{
  "tasks": [
    {
      "target_agent": "smm_agent|seo_agent|content_agent",
      "title": "Краткое название задачи",
      "description": "Детальное описание что нужно сделать",
      "priority": "high|medium|low",
      "deadline": "2026-05-30",
      "metrics": {
        "metric_name": "CTR карточки",
        "current_value": "1.2%",
        "target_value": "2.0%",
        "expected_impact": "+850 кликов/день"
      }
    }
  ]
}
```

### Когда создавать задачи

| Проблема | Кому | Пример задачи |
|----------|------|---------------|
| Низкий трафик из соцсетей | `smm_agent` | "Создать 3 поста про скидки на электронику" |
| Падение organic трафика | `seo_agent` | "Оптимизировать meta-теги для категории 'Одежда'" |
| Низкая конверсия на странице | `content_agent` | "Написать гайд 'Как выбрать наушники 2026'" |
| Низкий CTR на карточку | `content_agent` | "Обновить описания товаров с фокусом на выгоду" |
| Плохое удержание | `content_agent` | "Создать email-дайджест с персональными подборками" |

### Правила
1. Максимум **3 задачи** за один отчёт
2. Приоритет `high` — только если метрика упала >10% от нормы
3. Задачи должны быть **конкретными** — с цифрами и дедлайнами
4. Всегда указывай `expected_impact` — сколько метрика вырастет
